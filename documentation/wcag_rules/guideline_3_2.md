# WCAG 2.2 Guideline 3.2 Reference Rules

This ruleset contains the Success Criteria for **Guideline 3.2**.

## 📋 Criteria Summary

| ID | Success Criterion | Conformance Level |
| :--- | :--- | :---: |
| 3.2.1 | On Focus | `A` |
| 3.2.2 | On Input | `A` |

## ⚙️ Rules details

### Success Criterion 3.2.1 - On Focus (Level A)

> (Level A)

> When any user interface component receives focus, it does not initiate a change of context.

- [W3C Spec Link](https://www.w3.org/TR/WCAG22/#x3-2-1-on-focus)

---

### Success Criterion 3.2.2 - On Input (Level A)

> (Level A)

> Changing the setting of any user interface component does not automatically cause a change of context unless the user has been advised of the behavior before using the component.

- [W3C Spec Link](https://www.w3.org/TR/WCAG22/#x3-2-2-on-input)

---

### Success Criterion 3.2.3 - Consistent Navigation (Level AA)

> (Level AA)

> Navigational mechanisms that are repeated on multiple web pages within a set of web pages occur in the same relative order each time they are repeated, unless a change is initiated by the user.

- [W3C Spec Link](https://www.w3.org/TR/WCAG22/#x3-2-3-consistent-navigation)

---

### Success Criterion 3.2.4 - Consistent Identification (Level AA)

> (Level AA)

> Components that have the same functionality within a set of web pages are identified consistently.

- [W3C Spec Link](https://www.w3.org/TR/WCAG22/#x3-2-4-consistent-identification)

---

### Success Criterion 3.2.5 - Change on Request (Level AAA)

> (Level AAA)

> Changes of context are initiated only by user request or a mechanism is available to turn off such changes.

- [W3C Spec Link](https://www.w3.org/TR/WCAG22/#x3-2-5-change-on-request)

---
